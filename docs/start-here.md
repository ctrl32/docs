# Start here

One path, in order. Each step stands on the one before it and none of
them needs hardware until it says so.

1. **[Quick start](quickstart.md)** — install the editor, open a shipped
   example, run it in the simulation and put it on a board. Twenty
   minutes, and you have seen the whole round trip.
2. **[Your first project](tutorial.md)** — an empty file to something
   running: a screen, a few variables, a rung of ladder, the browser
   view. Half an hour, no hardware until the last step.
3. **[Tutorial projects](tutorials.md)** — complete projects built the
   same way, each around one thing: two boards over Modbus, a thermostat
   fed by Home Assistant, a drive over CAN.
4. **[Examples](examples.md)** — the shipped projects for the catalogue
   boards, to open and take apart.

When something does not behave, [Troubleshooting](troubleshooting.md)
lists the actual messages the system prints. And before you plan
anything real with it, read [Intended use](intended-use.md) — it is the
most important page here.
